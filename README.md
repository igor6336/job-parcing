# Ежедневный дайджест вакансий в Telegram

Парсер собирает вакансии со стажировками и junior-позициями по аналитике
(финансовый, бизнес-, BI-, системный, продуктовый аналитик) в Москве
и каждое утро присылает готовый список в Telegram.

Формат карточки: **компания · должность · зарплата · график · требования · ссылка на отклик**.

---

## Источники

| Источник | Доступ | Что отдаёт | Вклад в выдачу |
|---|---|---|---|
| **hh.ru** | RSS-выдача поиска | компания, зарплата, регион, дата | основной |
| **Работа России** (trudvsem.ru) | открытые госданные, JSON | всё, включая требования и график | заметный |
| **Хабр Карьера** | парсинг HTML | грейд, стек, формат работы | IT-аналитика |
| **getmatch.ru** | неофициальный JSON | зарплаты указаны почти везде | мало junior |
| **LinkedIn** | гостевой эндпоинт | компания, локация, дата | единицы |
| **SuperJob** | официальный API, нужен ключ | всё | зависит от ключа |

Падение любого источника не роняет запуск: в лог пишется ошибка, дайджест уходит
по тому, что удалось собрать.

---

## hh.ru: почему RSS, а не API

**В апреле 2026 hh закрыл публичный поиск вакансий через API.** `GET /vacancies`
отдаёт `403 Forbidden` всем неавторизованным клиентам — независимо от страны,
IP и User-Agent. Ключи теперь выдаются работодателям и рекрутинговым сервисам
после модерации приложения; соискателю его не получить.

Проверено на живых запросах — закрыт именно контент, а не домен:

| Эндпоинт | Ответ |
|---|---|
| `api.hh.ru/vacancies` | 403 |
| `api.hh.ru/employers` | 403 |
| `api.hh.ru/areas`, `/dictionaries`, `/suggests` | 200 |
| `hh.ru/search/vacancy/rss` | **200** |

Поэтому источник работает через **RSS-выдачу поиска** — штатную функцию самого
сайта, ссылка на которую есть на странице результатов. Это не обход блокировки
и не парсинг HTML-страниц, который правила hh запрещают отдельным пунктом.

**Прокси и VPS в России проблему API не решают** — блокировка не географическая.
Единственное, что даёт доступ к API, — аккаунт работодателя.

### Чем за это платим

RSS содержит только заголовок, компанию, регион, зарплату и дату. **Графика работы
и требований в нём нет** — у вакансий с hh эти строки в карточке просто не
выводятся, всё остальное на месте. Требования по-прежнему отдают trudvsem,
Хабр Карьера и getmatch.

Дотягивать детали со страницы вакансии парсер намеренно не умеет: это уже парсинг
HTML, прямо запрещённый правилами hh.

Ещё два ограничения фида: он игнорирует часть фильтров (`experience`, `period`
применяются нестрого) и отдаёт ровно 20 вакансий на страницу. Первое компенсирует
локальная фильтрация, второе — параметр `max_pages` и `search_field: name`,
который заставляет искать только по названию вакансии.

## LinkedIn: прочитайте перед включением

Источник работает, но ожидания стоит держать низкими — по трём причинам.

1. **Выдача по Москве тонкая.** Замер на живых запросах: «аналитик» — около 30
   вакансий всего, «financial analyst» — 10, «intern» — 7. С фильтром по свежести
   (3 дня) в дайджест попадают **единицы**. Для сравнения, hh за тот же прогон
   отдаёт полторы сотни. LinkedIn заблокирован в РФ с 2016 года, российские
   компании там почти не публикуются — остаются международные.
2. **Это не официальное API.** Гостевой эндпоинт `jobs-guest/...` отдаёт публичные
   карточки без авторизации, но LinkedIn его не документирует, а в пользовательском
   соглашении запрещает автоматизированный сбор данных. Формально — серая зона.
   Решение о применении за вами; отключается строкой `enabled: false` в `config.yaml`.
3. **В карточке нет требований**, а зарплату указывают редко.

Мой вывод: держать включённым можно — стоит он одного запроса в день и иногда
приносит стажировку в международной компании, которой нет на hh. Но строить
на нём расчёт не стоит.

## Быстрый старт

### 1. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение (иначе он не сможет вам писать).
3. Узнайте свой chat_id: откройте
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите `"chat":{"id":...}`.

### 2. Секреты репозитория

Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Обязателен | Значение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от BotFather |
| `TELEGRAM_CHAT_ID` | да | chat_id получателя; несколько — через запятую |
| `SUPERJOB_API_KEY` | нет | ключ с https://api.superjob.ru/register |
| `JOBPARSER_PROXY` | нет | прокси, если из вашей сети площадки недоступны |

### Несколько получателей

В `TELEGRAM_CHAT_ID` можно перечислить несколько чатов через запятую:
`1106920192,987654321`. Дайджест уйдёт каждому.

Два условия:

1. **Каждый получатель должен сам написать боту** хотя бы одно сообщение.
   Пока он этого не сделал, Telegram запрещает боту писать первым и
   возвращает «chat not found».
2. Узнать чужой chat_id можно там же, в `getUpdates` — после того как
   человек написал боту, его чат появится в ответе. Либо он присылает
   свой ID сам, получив его у [@userinfobot](https://t.me/userinfobot).

Сбой одного получателя не отменяет рассылку остальным: в лог пишется ошибка,
все остальные дайджест получают. Историю отправленного парсер обновляет,
если дошло хотя бы до одного, — иначе отвалившийся чат заставлял бы всех
получать один и тот же список каждый день.

**Важно:** фильтр один на всех и настроен под конкретное резюме (см. раздел
выше). Человеку с другим профилем выдача будет мимо — ему разумнее сделать
форк репозитория и поправить веса под себя.

### 3. Проверка

Actions → «Daily job digest» → Run workflow → включите `dry_run`, чтобы
посмотреть результат без отправки в Telegram.

Дальше запуск происходит автоматически.

### Локальный запуск

```bash
pip install -r requirements.txt
python -m jobparser.main --dry-run --no-dedup        # показать, ничего не отправляя
python -m jobparser.main --out digest.md             # сохранить в Markdown
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... python -m jobparser.main
```

Флаги: `--dry-run`, `--no-dedup`, `--limit N`, `--out FILE`, `--config PATH`, `--verbose`.

## Время отправки

Cron стоит на `45 4 * * *` — это **07:45 МСК**, а не 08:00, и это сделано намеренно:
планировщик GitHub Actions при высокой нагрузке опаздывает на 5–20 минут, поэтому
запуск ставится с запасом и сообщение приходит примерно к восьми утра.

Точность до минуты GitHub Actions не даёт в принципе. Если время критично —
переносите запуск на cron собственного сервера.

Поменять время: `cron` в `.github/workflows/daily-jobs.yml` (всегда UTC, МСК = UTC+3).

## Настройка под профиль кандидата

Фильтр настроен под конкретный профиль: бизнес-анализ (BPMN 2.0, MS Visio),
BI (Power Query, Яндекс DataLens), продвинутый Excel, финансовый домен,
SQL на базовом уровне, английский B1, студент с занятостью 20–30 ч/нед.

Профиль задаётся четырьмя блоками в `config.yaml`. Все они — просто веса,
менять их можно без изменения кода.

| Блок | Что делает | Пример |
|---|---|---|
| `role_keywords` | роль в названии → вес | `бизнес аналитик: 9`, `аналитик данных: 5` |
| `internship_weight` / `junior_weight` | стажировка ценится выше junior | `9` против `2` |
| `query_profiles` (hh) | режимы поиска площадки → бонус | `employment: probation` → `+9` |
| `skill_keywords` | навык из резюме в требованиях → плюс | `bpmn: 3`, `power query: 3` |
| `skill_gaps` | чужой стек → минус | `python: -2`, `1с: -3` |
| `schedule_bonus` | график, совместимый с учёбой | `неполн: 5`, `полный день: -1` |

Роль выбирается по **лучшему** совпадению, а не по первому: «Младший
бизнес-аналитик» матчит и широкий якорь `аналитик` (3), и точную
`бизнес аналитик` (9) — засчитывается девятка.

Вакансии ниже `min_score` в дайджест не попадают. Порог 9 выбран по замеру
на живой выдаче: он отсекает 1С-аналитиков и HR-аналитику, оставляя
профильные позиции с запасом.

### Что настройка даёт на реальных данных

Замер на одном прогоне: из 1032 собранных вакансий базовый фильтр пропускает
45, профильный порог оставляет 36. Наверху оказываются «Младший бизнес-аналитик»,
«Младший BI-аналитик», «Стажер группы бизнес-аналитики»; внизу и за порогом —
«Стажер-аналитик 1С», «HR-аналитика».

### Стажировки вместо junior

При занятости 20–30 ч/нед junior на полный день чаще всего не подходит, поэтому
стажировка весит заметно больше (9 против 2).

Главный рычаг — не слова в названии, а режимы поиска hh. Фид уважает параметры
`employment` и `schedule` (в отличие от `experience`, который игнорирует), так что
стажировки запрашиваются напрямую:

| Режим | Параметр | Бонус |
|---|---|---|
| стажировка | `employment=probation` | +9 |
| гибкий график | `schedule=flexible` | +5 |
| неполный день | `schedule=partTime` | +5 |
| обычный поиск | — | 0 |

Площадка подтверждает тип занятости, даже если слова «стажёр» в заголовке нет.
Обратная сторона: junior на полный день из обычного поиска до порога `min_score`
теперь не дотягивает — это сделано намеренно.

### Границы этой настройки
- **`skill_gaps` не отсекает, а опускает.** Python в требованиях junior-вакансии
  часто идёт как «будет плюсом», поэтому жёсткий отказ терял бы хорошие позиции.
- **Требования видны не у всех источников**, значит `skill_keywords`
  и `skill_gaps` на вакансиях с hh не срабатывают — там работают только
  роль, уровень, зарплата и свежесть.

### Если профиль изменится

Выросли в SQL — поднимите вес `аналитик данных` и `data analyst` до 7–8
и уберите `sql` из `skill_keywords` (он перестанет быть отличительным).
Освоили Python — перенесите его из `skill_gaps` в `skill_keywords`.
Готовы к полной занятости — уберите минусы из `schedule_bonus`.

## Как настроить под себя

Всё поведение задаётся в `config.yaml`, код трогать не нужно.

- `role_keywords` — какие роли ищем. **Проверяются только по названию вакансии:**
  поиск по всему описанию давал мусор, потому что слово «аналитика» встречается
  в обязанностях почти любой офисной вакансии.
- `level_keywords` — маркеры стажировки/junior (проверяются и в названии, и в описании).
- `title_stopwords` — мгновенный отказ по названию (senior, ведущий, консультант…).
- `experience_stopwords` и `max_experience_years` — отсечение по требуемому опыту.
- `max_results` — сколько вакансий максимум в одном дайджесте.
- `period_days` — за сколько дней брать вакансии.

Совпадение идёт по началу слова: `аналитик` ловит «аналитика», «аналитику»,
«бизнес-аналитика», но не срабатывает внутри постороннего слова.

Ослабить фильтр (если вакансий приходит слишком мало) — уберите часть
`title_stopwords` или добавьте роли в `role_keywords`. Ужесточить — сократите
`role_keywords`, убрав широкие якоря `аналитик` и `финанс`.

## Как это работает

```
источники → общая модель Vacancy → фильтры/скоринг → дедупликация → Telegram
```

1. Каждый источник приводит свою выдачу к единой модели `Vacancy`.
2. `filters.py` отбрасывает нерелевантное и ранжирует остальное:
   роль в названии (+4), уровень в названии (+4) или в описании (+2),
   указанная зарплата (+1), свежесть (+3 за сутки).
3. Дубли между площадками схлопываются по паре «компания + должность».
4. `state/seen.json` помнит уже отправленное, поэтому одна вакансия не приходит дважды.
   Файл коммитится обратно в репозиторий самим workflow; записи старше 60 дней удаляются.
5. Дайджест режется на сообщения так, чтобы не упираться в лимит Telegram (4096 символов)
   и не разрывать карточку вакансии пополам.

Состояние обновляется **только после успешной отправки** — иначе при сбое Telegram
вакансии были бы помечены отправленными, но вы бы их не увидели.

## Добавить свою площадку

1. Создайте `jobparser/sources/<name>.py`, унаследуйтесь от `BaseSource`,
   реализуйте `fetch() -> list[Vacancy]`.
2. Зарегистрируйте класс в `jobparser/sources/__init__.py`.
3. Добавьте секцию в `config.yaml` → `sources`.

Фильтрацию писать не нужно — она общая для всех источников.

Кандидаты на добавление: rabota.ru и zarplata.ru (проверено — отвечают, но требуют
парсинга HTML), career-страницы конкретных компаний, Telegram-каналы с вакансиями.

## Ограничения, о которых стоит знать заранее

- **У вакансий с hh нет графика и требований** — следствие закрытия API,
  подробности выше. Остальные поля на месте.
- **Хабр Карьера парсится из HTML** — при редизайне сайта источник сломается.
  Это видно в логе (`карточки не найдены`), остальные площадки продолжат работать.
- **getmatch и гостевой эндпоинт LinkedIn — неофициальные**, могут измениться
  или закрыться без предупреждения. Как закрылся API hh.
- **Дни, когда ничего нет, — норма.** При `period_days: 3` и работающей
  дедупликации пустой дайджест пару раз в неделю ожидаем.
- Парсер **не откликается** за вас, только присылает ссылки.
